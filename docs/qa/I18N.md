# Internationalization checks

Every user-facing string exists in English and Bengali (F-I18N-001, F-I18N-009). Three checks enforce this; all run in CI's `verify` job.

| Check | Where | Fails when |
|---|---|---|
| **No literal text** | ESLint, `@dgd/config/eslint/ui` (apps/web and packages/ui) | Latin or Bengali letters appear in JSX text, in a `{'…'}` or template child, or in the value of a user-visible attribute (`aria-label`, `aria-description`, `title`, `placeholder`, `alt`, `label`), including either branch of a conditional. Text comes from the catalogs (`getTranslations` / `useTranslations`) in apps, or from props in `packages/ui`. |
| **Catalogs complete** | `packages/i18n/src/messages.spec.ts` | `bn.json` and `en.json` don't have exactly the same keys, or any message is empty. |
| **Client namespaces** | TypeScript: `useClientTranslations` (`apps/web/src/i18n/client.ts`), plus a lint ban on importing next-intl's `useTranslations` elsewhere in the app | A client component uses a namespace that isn't sent to the browser (`CLIENT_NAMESPACES` in `apps/web/src/i18n/client-namespaces.ts`). This is a type error; without the check the page would show the raw key at runtime. |

## Allowlist

| Exempt | Why |
|---|---|
| `*.stories.tsx` | Storybook stories hold their own sample copy in both languages. |
| `*.e2e.tsx` | Routes compiled only into the E2E build. They never ship. |
| Text without letters | Punctuation, separators and numbers rendered from variables (`{a} · {b}`) carry no language. |

Anything else needs an inline `// eslint-disable-next-line no-restricted-syntax -- <reason>` comment, which shows up in review. There are none today.

## Conventions

- **Bengali is not optional.** A key is added to both catalogs in the same change. The Bengali reviewer checks BN copy before release (DESIGN_SYSTEM §7).
- **Server first.** Server components use `getTranslations` and send nothing extra to the browser. Client components use `useClientTranslations`, and their namespaces go in `CLIENT_NAMESPACES`.
- **One UI lint preset.** `@dgd/config/eslint/ui` holds both the raw-colour and the literal-text rules, in two file scopes that never overlap. Both rules are `no-restricted-syntax`, and a later flat config would replace an earlier one's options.
