### Added (2026-10-31), Phase 2: T-P2-PLAT-004 background worker (pg-boss 12.38)
- **Entrypoint:** `apps/api/src/worker.ts` (`pnpm worker`). It is a Nest application context with no HTTP, in the same codebase as the API (DL-036).
- **Job definitions:** each job is a provider marked `@Job({ name, schema, queue?, concurrency?, schedule? })` with a Zod payload. `JobRunner` discovers them. For each one it creates the queue plus `<name>.dlq` and validates every payload before handling. Recurring jobs are scheduled in UTC unless a time zone is given.
- **Defaults (ADR-005):**
  - 3 retries with exponential backoff (30 s up to 1 h).
  - Terminal failures are kept in `<name>.dlq` for inspection and retry (ADMIN-014). A non-empty DLQ raises a pg-boss `queue_backlog` warning, which is logged.
  - Idle polling every 10 s (`JOB_POLL_SECONDS`).
  - Direct (unpooled) Neon URL with a pool of 3 (DL-026).
- **Graceful shutdown:** SIGTERM or SIGINT stops fetching and waits up to 25 s for in-flight jobs to finish.
- **Heartbeat job:** `system.heartbeat`, hourly.
- **Config:** split per process. The API needs `DATABASE_URL`; the worker needs `DIRECT_URL`. Both share `NODE_ENV` and `LOG_LEVEL`.
- **TLS:** connection strings now use `sslmode=verify-full`. Neon supports full certificate verification, and `pg`'s current alias would weaken to libpq `require` semantics in its next major version.
- **Tests: 28 passing.** The new worker integration tests run on the Neon `test` branch and cover:
  - a job enqueued and completed
  - a bad payload failing and reaching the DLQ
  - an in-flight job drained on shutdown and ending `completed`
- **Real run:** the built worker connected to `dev`, created the heartbeat queue, and processed a manually enqueued heartbeat.
  - On Windows, SIGTERM can't be delivered to Node, so drain behaviour was verified through `app.close()`, which is the same shutdown-hook path that SIGTERM triggers on Linux hosts.
- **Pre-push review of T-P2-PLAT-004:**
  - **Typed producer:** a job's contract is a `defineJob({ name, schema, queue?, schedule? })` value shared by producers and handlers. `JobsClient.send()` validates the payload before enqueueing. The API wires it in with its first producer, `email.send` in T-P2-INTG-001.
  - **Handler context:** handlers receive `{ jobId, retryCount, signal }`. The `signal` aborts on shutdown. Handlers must be idempotent because a job can rerun after a retry or an interrupted deploy.
  - **Dead-letter queues are no longer consumed.** Dead jobs stay `created` in the DLQ, and `warningQueueSize: 1` raises a backlog warning. This also removes one poller per queue.
  - **Queue setup:**
    - Queue options are re-applied on every boot (`updateQueue`).
    - Queues register in parallel.
    - Schedules no longer declared in code are removed at boot.
    - Discovery uses Nest's typed `DiscoveryService.createDecorator`.
  - **TLS is enforced in config:** remote database URLs must use `sslmode=verify-full`, and boot fails otherwise (test added).
  - **Neon idle load:**
    - pg-boss internal timers are tuned down, the heartbeat moved from every 5 minutes to hourly, and the always-on decision is recorded in ADR-005.
    - With pg-boss defaults, a running worker made about 2,600 idle queries per hour, and Neon cannot suspend while it runs.
  - **Shared helpers:** `runOrExit` handles boot failures for both entrypoints, and `createTestWorker` boots the real worker module in tests. The tests use `vi.waitUntil`.
  - **Tests:** 30 passing. The worker integration tests cover the typed send, send-time rejection, the DLQ keeping a dead job, and drain on shutdown.

### Added (2026-10-31), Phase 2: T-P2-PLAT-005 web app skeleton (`apps/web`)
- **Stack:** Next.js 16.4 (App Router, Turbopack), React 19.3, TypeScript 6 (strict) and Tailwind CSS 4. Design tokens arrive with T-P2-UI-001.
- **Routing:**
  - Every page lives under `/{locale}` (en | bn).
  - `proxy.ts` (Next 16's replacement for `middleware.ts`) redirects locale-less URLs using the cookie, then `Accept-Language`, then English.
  - There is one root layout per locale, so `<html lang>` is always correct.
  - Messages come from a small typed per-locale dictionary until next-intl and `packages/i18n` land (T-P2-I18N-001). No user-facing string is hardcoded.
- **Route groups:** `(public)` (landing), `(app)` (Today placeholder) and `admin` (dashboard placeholder), each with its own layout.
  - Each group re-exports a shared, accessible loading state.
  - Error and not-found boundaries are localized and never show error details.
  - A `[...rest]` catch-all gives unmatched URLs the localized 404, with a real 404 status.
  - `notFound()` inside a streaming route group returns Next's "soft 404": HTTP 200 plus `noindex`.
- **API access:** `lib/api.ts` is a typed `apiFetch` that turns problem+json errors into `ApiError`. Response types will be generated in T-P2-PLAT-006.
  - The landing page shows live API and database readiness, and degrades to "temporarily unavailable" if the API is down or slow (3 s cap).
- **Lint:** ESLint uses `eslint-config-next` (core-web-vitals) with the shared base applied last, so the TypeScript parser covers every file.
- **Playwright smoke tests:** 14 passing (7 tests × desktop and mobile) against a production build. They cover:
  - the locale redirect
  - EN and BN rendering
  - all three route groups
  - the 404 for unknown pages and locales
  - the streamed loading state
  - the error boundary hiding details
  - API-down degradation
  - The loading and error cases run through a test-only route that is disabled unless `E2E_ROUTES=1`.
- **Real run:** the built web app on a spare port, against the API on Neon `dev`.
  - `/` redirected a Bengali browser to `/bn`, and `/bn` showed "সবকিছু ঠিকঠাক চলছে".
  - `/en` showed "unavailable" on the very first request (Neon cold start), then "All systems working".
  - Ports 3000 and 3001 were already taken by other programs on this machine, so the scripts now honour `PORT`.
- **Pre-push review of T-P2-PLAT-005:**

  - **Loading states:** `loading.tsx` is now allowed only in leaf segments, and the convention is documented in `components/route-loading.tsx`. Group-level loading made every `notFound()` beneath it return HTTP 200, a "soft 404". Unknown URLs keep a real 404.
  - **Test-only routes:** the `*.e2e.tsx` routes compile only in E2E builds (`pageExtensions`, separate `.next-e2e` output). They never ship, and the normal build was checked to contain none of them. Playwright runs one dedicated build per run and never reuses a stale server.

  - **Smaller code:** a `routeMessages()` helper, a simpler `ApiError(status, problem?)`, role-based test selectors instead of test-only attributes, and removed default or unused config.

### Added (2026-10-31), Phase 2: T-P2-PLAT-008 security baseline
- **API headers (Helmet, NFR-SECURITY-014/015):**
  - CSP `default-src 'none'; frame-ancestors 'none'`, which suits a JSON API.
  - `nosniff` and `strict-origin-when-cross-origin`.
  - HSTS with preload in production only.
  - The Swagger UI (non-production only) gets its own relaxed policy.
- **CORS (NFR-SECURITY-027):** credentialed, limited to `WEB_ORIGINS`.
  - `WEB_ORIGINS` is required and validated in production; development defaults to `localhost:3000` and `3210`.
  - Unknown origins get no CORS headers, preflights included.
- **Rate limiting (`@nestjs/throttler`, tiers per API_CONVENTIONS §10):**
  - `default` allows 300/min and `write` allows 120/min for mutations.
  - 429 responses carry a standard `Retry-After` header and a `RATE_LIMITED` problem with `retryAfterSec`.
  - Health probes are exempt.
  - `TRUST_PROXY` makes the per-IP limits see real client IPs.
  - `auth-strict` and the Postgres-backed login/reset counters arrive with the auth endpoints, which already plan them.
- **Request limits:** a JSON depth limit of 32 is checked in one byte pass before parsing, on top of the 256 KB body limit. Brackets inside strings don't count.
- **Web (NFR-SECURITY-015):**
  - A strict CSP with a fresh nonce per request (`proxy.ts`): no `unsafe-inline` scripts, `strict-dynamic`, and `frame-ancestors 'none'`. Development adds only `unsafe-eval` and `ws:`.
  - Static headers: `nosniff`, a referrer policy, `X-Frame-Options`, a `Permissions-Policy` (geolocation same-origin for prayer times, camera and microphone off), and HSTS in production.
  - Pages now render per request, because a nonce can't be baked into static HTML. The landing page's API status stays fetch-cached for 60 s, so this adds no API or database load.
- **Dev fix:** on Windows, `pnpm dev` crashed on the first file change: Nest's watcher couldn't kill the app process when launched through `--exec`. `.env` is now loaded into the Nest CLI process, and restarts were verified after two file changes.
- **Tests:**
  - API: 41 passing, including new tests for headers, CORS (allowed, unknown, preflight), the depth limit (including brackets inside strings), health probes never being throttled, and the write tier returning 429 with `Retry-After`.
  - Web E2E: 12 passing, including the nonce on every script with no CSP violations while the page still hydrates, and the static headers.
  - Dev mode was checked in a real browser.
- **Pre-push review of T-P2-PLAT-008:**
  - **Rate limiting behind a proxy (the main fix):** `TRUST_PROXY` is now required in production, alongside `WEB_ORIGINS`; an explicit `0` is allowed. With the default of 0, every client behind the host's proxy would have shared one rate-limit bucket.
  - **Rendering trade-off:** the nonce CSP's per-request rendering is recorded as DL-038, and the architecture rendering table is updated. A hash-based CSP spike for public pages is planned in T-P10-QA-003.
  - **Headers:**
    - The API now sends `X-Frame-Options: DENY`, consistent with the web app.
    - In production `/docs` also gets the strict headers.
    - One shared `DOCS_PATH` constant.
    - Per-tier `X-RateLimit-*` and `Retry-After-write` headers are gone; only the standard `Retry-After` is sent on 429.
  - **Dev script:** `pnpm dev` now uses the Nest CLI's built-in `--env-file`, again verified to restart cleanly on file changes on Windows.

### Added (2026-10-31), Phase 2: T-P2-PLAT-009 observability
- **`@dgd/observability` (new package):**
  - `scrubEvent` and `scrubString`, the NFR-PRIVACY-010 safety net for every error report:
    - Values under sensitive keys are redacted at any depth.
    - Request bodies and cookies are dropped.
    - Emails keep only their domain.
    - URL credentials and secret query parameters (`token`, `code`, `*key*`…) are removed.
  - `@dgd/observability/node` exports `createNodeReporter`, shared by the API, the worker and the web server:
    - Sentry errors only, with no tracing and no integrations.
    - A scope per report.
    - A no-op when no DSN is set.
- **API and worker:**
  - The `ErrorReporter` provider reports 5xx responses (tagged with `requestId`), a job's final failed attempt once retries are exhausted (tagged with `queue`, `jobId`, `retryCount`), and pg-boss errors.
  - New config: `SENTRY_DSN` and `APP_RELEASE`.
- **Web:**
  - `onRequestError` reports server errors tagged with `requestId`, route and digest.
  - The browser loads `@sentry/browser` lazily, and only when `NEXT_PUBLIC_SENTRY_DSN` is set. `error.tsx` reports errors caught by the boundary.
  - `proxy.ts` gives every page an `X-Request-Id` (a well-formed upstream UUID is kept) and forwards it to the API through the API client, so one id spans web and API logs and reports.
  - The CSP allows the Sentry ingest origin only when a DSN is set.
- **CSP violation reports:**
  - `report-to csp`, `Reporting-Endpoints` and a `report-uri` fallback point browsers to `/api/csp-report`.
  - That endpoint accepts both report formats, caps bodies at 16 KB, and logs one `warn` line per violation with URLs reduced to origin and path.
- **Docs:**
  - `docs/architecture/OBSERVABILITY.md` covers reporting, correlation, privacy rules and structured log field conventions.
  - The decision is recorded as DL-039.
  - `.env.example` files were added for the API and the web app.
- **Tests:**
  - Observability: 7 unit tests.
  - API: 43 passing, including a Sentry wire-envelope test that uses the real reporter with a capturing transport. It checks release, environment and the `requestId` tag matching `X-Request-Id`, and that no DB password or email is sent.
  - Web E2E: 15 passing, covering the request id, CSP reporting headers, both report formats, and 400/413 handling.
- **Verified manually against a fake Sentry ingest** (production build with a DSN):
  - The server event arrived with the release, a `requestId` equal to the page's `X-Request-Id`, the route and the digest.
  - The browser event arrived with the same release and digest, and its `?token=` was redacted.
  - The CSP allowed the request.
- **Pre-push review of T-P2-PLAT-009:**
  - **One privacy list:** `SENSITIVE_FIELDS` in `@dgd/observability` now drives both Sentry scrubbing and the pino `redact` paths. Before, the two lists had already drifted apart: logs did not redact `apiKey`, `journal` or `session`.
  - **Logged errors are scrubbed too:** an error message containing a DB connection string was safe in Sentry but was written to the logs verbatim.
  - **Final attempts only:** the worker reports a job only after its last attempt, so a failure fixed by a retry is no longer a Sentry incident.
  - `@sentry/node` loads only when a DSN is set, so dev, test and CI processes don't pay its startup cost. The browser scrubber is lazy-loaded with the SDK.
  - **Smaller cleanups:** the scrubber no longer tracks paths per node, one `[REDACTED]` marker is used everywhere, and there is one field map for both CSP report formats.
  - **Accepted, not changed:**
    - Process-level `uncaughtException`/`unhandledRejection` reporting is not added: the process exits before an async report is sent, and host logs record crashes.
    - The CSP endpoint has no rate limit beyond its 16 KB cap; edge limits come with T-P2-PLAT-010.
    - Web route handlers under `/api/*` get no request id, because the proxy skips them.
- **Not yet:** private source-map upload and setting the release to the git SHA belong to the deploy pipeline (T-P2-PLAT-010). The `userId` pseudonym in logs arrives with auth.
